# PMS 정책 인덱스

이 디렉터리는 현재 유효한 업무 정책을 영역별로 정리한다. 기획 이력이나 폐기된 정책은 포함하지 않는다.

## 문서 해석 원칙

- 코드와 데이터베이스 제약이 문서와 다르면 차이를 확인해 유효 정책에 맞출 구현 범위를 별도로 결정한다.
- 시작 시각은 별도 표기가 없으면 포함한다. 종료 시각의 포함 여부는 각 영역에 명시한다.
- 관리자 화면의 버튼 노출만으로 권한을 판단하지 않는다. 애플리케이션 서비스와 저장 트랜잭션이 함께 강제하는 조건을 기준으로 한다.
- 정책 결정이 남았거나 서로 충돌하는 선택지가 있는 항목은 유효 정책으로 확정하지 않고 [확인 필요 정책](open-questions.md)에 둔다.
- 이 문서들은 결정 기록이 아니다. 폐기된 정책과 논의 과정은 남기지 않는다.

## 코드 검토 범위

- `prisma/schema.prisma`와 현재 모델의 제약을 만드는 마이그레이션을 확인한다.
- `src/modules`의 도메인·애플리케이션·인프라 계층을 모두 확인한다.
- `src/app`의 Server Action과 Route Handler를 모두 확인해 인증, 입력 제한, 상태 전이를 대조한다.
- 페이지와 UI 코드는 진입점 노출, 상태 안내, 서버 정책과의 불일치를 확인하는 용도로 대조한다.
- 테스트와 시드 데이터는 정책의 근거가 아니라 구현 의도를 교차 확인하는 보조 자료로만 사용한다.

## 상태 모델 요약

- 프로그램 종료 여부는 별도 상태가 아니라 현재 시각과 `endsAt`만으로 판정한다.
- 프로젝트에 저장하는 상태는 `PENDING_APPROVAL`, `REJECTED`, `ACTIVE`뿐이다.
- `ACTIVE` 프로젝트의 표시 상태는 프로그램 종료 전에는 팀 확정 여부에 따라 `FORMING` 또는 `IN_PROGRESS`, 종료 뒤에는 `COMPLETED` 또는 `CANCELED`로 파생한다.
- 반려 프로젝트의 재검토는 기존 승인 이력을 보존한 새 요청으로 처리하고, 승인은 기존 검증 트랜잭션을 다시 사용한다.
- 프로젝트 팀은 상태를 저장하지 않는다. `confirmedAt`은 팀 확정 사실만 나타낸다.
- 학생 팀은 프로젝트와 독립적으로 유지되며 삭제 시각으로 활성 여부를 구분한다.
- 보고서 버전은 제출 후 최신 버전에 한 번만 승인 또는 수정 요청 결정을 남긴다.
