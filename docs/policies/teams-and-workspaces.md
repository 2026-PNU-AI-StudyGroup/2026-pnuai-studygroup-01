# 팀과 프로젝트 공간 정책

## 학생 팀

- 학생 팀은 특정 프로그램이나 프로젝트에 종속되지 않는 사전 구성 팀이다.
- 활성 학생만 팀을 만들며 생성자가 팀장이자 첫 팀원이 된다.
- 팀 이름은 1~80자, 설명은 1,000자 이하다.
- 팀장만 초대, 팀장 이전, 팀원 제외, 팀 삭제를 할 수 있다.
- 초대는 본인을 제외한 부산대학교 이메일로 보낸다. 가입 전 이메일에도 초대할 수 있다.
- 초대 수락 시점에는 초대 이메일과 로그인 이메일이 같고 계정이 활성 학생이어야 한다.
- 팀장은 본인을 제외할 수 없으며, 탈퇴 대신 다른 현재 팀원에게 팀장을 이전해야 한다.
- 일반 팀원은 스스로 탈퇴할 수 있다. 팀장은 다른 현재 팀원에게 팀장을 이전한 뒤 탈퇴할 수 있다.
- 팀원 수락·제외·팀장 이전은 팀 구성 버전을 증가시킨다.
- 프로젝트 승인 대기 중인 팀에는 새 초대를 보낼 수 없다.
- 팀 삭제는 대기 초대를 취소하고 모집 글을 닫으며 대기 모집 지원과 프로젝트 승인 요청을 반려한다.

## 학생 팀원 모집

- 팀원 모집의 조회·작성·지원은 학생만 사용한다. 지원자 검토는 팀장과 관리자가 할 수 있다.
- 팀장만 현재 인원보다 큰 정원을 지정해 모집 글을 만든다.
- 모집 정원은 2~100명이다.
- 제목은 1~200자, 내용은 1~2,000자, 역할·활동 가능 시간은 각각 1~500자다.
- 필수 기술은 1~20개이며 항목당 50자 이하다.
- 마감은 등록 시점 이후부터 달력 기준 한 달 이내다.
- 학생은 자신이 이미 속한 팀이나 같은 글에 다시 지원할 수 없다.
- 지원 내용은 1~2,000자, 희망 역할은 1~500자다.
- 지원 수락 시 지원자가 여전히 활성 학생 계정인지 다시 확인한 뒤 팀원을 추가하고 구성 버전을 증가시킨다.
- 팀 정원이 차면 해당 팀에서 정원 이하로 설정된 모든 공개 모집 글을 닫는다.
- 팀장이 모집 글을 직접 닫을 수 있다.
- 마감 시각이 지나면 새 지원과 지원 처리는 불가능하지만 글 상태 값은 별도 작업 없이 `OPEN`으로 남을 수 있다.

## 실행 팀과 접근

- 프로젝트 지원이 처음 승인되면 `FORMING` 실행 팀을 만들고 첫 승인 학생을 팀장으로 지정한다.
- 학생 제안 프로젝트는 승인과 동시에 기존 학생 팀 구성으로 `CONFIRMED` 실행 팀을 만든다.
- 구성 중인 실행 팀은 팀원이 한 명 이상일 때 담당교수·조교·관리자가 확정할 수 있다.
- 실행 팀 확정 시 남은 프로젝트 지원과 실행 팀 모집 지원을 미선정하고 모집 글을 닫는다.
- 실행 팀 공간은 실행 팀원, 담당교수, 프로젝트 조교, 관리자가 조회한다.
- 프로젝트 팀은 별도 종료 상태가 없다. 프로그램 종료 전에는 일반 구성 변경을 허용하고 종료 뒤에는 모든 구성 변경을 금지한다.
- 일반 팀원은 자진 탈퇴할 수 있고, 현재 팀장과 관리자는 일반 팀원을 제외할 수 있다. 팀장은 먼저 다른 현재 팀원에게 팀장을 이전해야 탈퇴하거나 제외할 수 있다.
- 탈퇴·제외는 행을 삭제하지 않고 `endedAt`과 종료 사유를 기록하며 프로젝트 권한을 즉시 회수한다.
- 프로그램 종료 뒤에는 관리자도 구성원을 종료·복구하거나 팀장을 변경할 수 없다.

## 프로젝트 정보

- 진행 중인 `CONFIRMED` 팀의 프로젝트명과 설명만 수정할 수 있다.
- 프로젝트명은 1~200자, 설명은 1~8,000자다.
- 관리자, 담당교수, 프로젝트 조교, 실행 팀장이 수정할 수 있다.
- 프로젝트명과 설명은 원 프로젝트의 제목과 설명에 반영한다. 실행 팀 이름은 바꾸지 않는다.

## 진행률 표시

- 프로젝트 진행률은 필수 보고서 중 한 번이라도 제출된 보고서의 비율을 반올림한 값이다. 승인 여부와 할 일 완료율은 반영하지 않는다.
- 필수 보고서가 없으면 0%가 아니라 `일정 없음`으로 분류한다.
- 진행 구간은 0% 착수 전, 1~25% 초기, 26~50% 중반, 51~75% 후반, 76~99% 마무리, 100% 완료다.
- 제출 이력이 없는 필수 보고서가 마감 시각을 지났으면 기한 초과로 계산한다.

## 할 일과 대화

- 할 일과 팀 대화는 종료되지 않은 실행 팀에서만 새로 만들거나 변경한다.
- 할 일 변경은 실행 팀원과 관리자만 가능하다. 담당교수와 조교는 팀 공간을 볼 수 있지만 할 일을 변경하지 않는다.
- 할 일 제목은 1~200자이며 마감은 유효한 일시여야 한다. 과거 일시는 별도로 금지하지 않는다.
- 담당자는 같은 실행 팀의 학생만 지정할 수 있다.
- 상태는 `TODO`, `IN_PROGRESS`, `DONE`이며 완료 시 완료 시각을 저장하고 다시 열면 제거한다.
- 대화는 팀원·담당교수·조교·관리자가 작성하며 1~2,000자다.

## 지도 요청

- 지도교수 기능이 켜진 프로그램의 `CONFIRMED` 팀에서 실행 팀원만 회의 또는 검토 요청을 만든다.
- 같은 학생은 같은 팀에서 같은 종류의 대기 요청을 하나만 가질 수 있다.
- 제목은 2~100자, 내용은 5~2,000자다.
- 참고 링크는 선택 사항이며 HTTP 또는 HTTPS, 최대 2,048자다.
- 학생의 회의·검토 요청에는 별도 일시 입력을 두지 않는다. 필요한 일정 제안은 요청 내용에 적는다.
- 담당교수·조교·관리자가 대기 요청에 2~2,000자 답변을 남긴다.
- 회의 요청 답변에는 현재 이후이면서 프로그램 수행 종료 이하인 확정 일시 하나를 선택적으로 넣을 수 있다. 검토 요청 답변에는 확정 일시를 넣지 않는다.
- 요청자는 자신의 대기 요청을 취소할 수 있다.
- 프로그램 종료 후처리 시 남은 대기 요청은 자동 취소한다.

## 프로젝트 조교

- 담당 프로젝트를 감독할 수 있는 사용자는 역할과 관계없이 가입된 활성 사용자를 이메일로 초대한다.
- 프로젝트 담당자 본인은 조교가 될 수 없고, 같은 프로젝트에 중복 초대·등록할 수 없다.
- 초대받은 사용자가 수락해야 조교 권한이 생긴다.
- 조교는 프로젝트·지원서·실행 팀·보고서·평가·지도 요청의 감독자 권한을 가진다.
- 조교도 다른 조교를 초대하고 대기 초대를 취소하거나 기존 조교를 제거할 수 있다.
- 조교 권한을 제거하면 그 조교가 보낸 아직 대기 중인 조교 초대도 취소한다.
