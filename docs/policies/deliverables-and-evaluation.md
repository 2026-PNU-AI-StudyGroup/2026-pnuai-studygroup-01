# 보고서·결과물·평가 정책

## 프로그램 보고서 정의

- 관리자만 프로그램의 보고서 정의를 만들고 수정·정렬·보관한다. 프로그램 종료 여부는 관리 작업을 막지 않는다.
- 제목은 1~100자이며 같은 프로그램의 활성 정의에서 대소문자를 무시하고 고유하다.
- 마감은 프로그램 제출 기간 안에 있어야 한다. 관리자 설정에서는 과거 시각도 허용하며 제출 기간의 종료 시각을 포함한다.
- 새 정의는 종료되지 않은 기존 실행 팀에도 필수 보고서로 할당한다.
- 제출 이력이 생기면 정의 제목을 바꿀 수 없다.
- 새 마감이 기존 최신 제출 시각보다 앞설 수 없다.
- 제출 이력이 없는 정의를 보관하면 정의와 할당 보고서를 삭제한다.
- 제출 이력이 있는 정의를 보관하면 이력을 유지하고 종료되지 않은 팀의 해당 보고서를 필수 대상에서 제외한다.

## 보고서 제출과 검토

- `CONFIRMED` 팀의 실행 팀원과 관리자가 필수·활성 보고서의 새 버전을 제출할 수 있다.
- 실행 팀원은 프로그램이 `ACTIVE`이고 제출 시각이 제출 기간, 프로그램 종료, 개별 보고서 마감 이하여야 한다. 관리자는 이 시간 제한을 받지 않는다.
- 설명은 선택 사항이며 최대 2,000자다.
- 제출 파일은 같은 팀과 제출자 소유의 완료된 보고서 파일이어야 한다.
- 버전 번호는 보고서 안에서 1부터 순서대로 증가한다.
- 담당교수·조교·관리자는 `CONFIRMED` 팀 보고서의 결정 없는 최신 버전만 승인하거나 수정 요청할 수 있다.
- 수정 요청은 1~2,000자 사유가 필요하고, 승인은 선택적 2,000자 의견을 가질 수 있다.
- 한 보고서 버전에는 결정 하나만 저장한다.
- 담당교수·조교·관리자는 보고서 단위 피드백을 1~2,000자로 추가할 수 있다.
- 프로젝트가 종료된 뒤에도 담당교수·조교·관리자는 보고서에 보충 피드백을 추가할 수 있다. 종료 상태만을 이유로 피드백 작성을 막지 않는다.
- 보고서 제출·승인 여부는 프로젝트나 실행 팀의 종료 조건이 아니다. 프로그램 운영 기간 종료 시 보고서 상태는 그대로 보존하며 자동 승인·반려하지 않는다.

## 파일 업로드

- 보고서 파일은 PDF, DOC, DOCX만 허용하고 최대 25MiB다.
- 결과물 파일은 위 형식과 ZIP, PPT, PPTX, MP4, WebM, PNG, JPEG를 허용하고 최대 1GiB다.
- 파일명은 1~255자, 크기는 1바이트 이상, SHA-256은 소문자 64자리 16진수여야 한다.
- 업로드 목적과 최종 소비 영역이 일치해야 한다.
- 종료되지 않은 팀의 실행 팀원 또는 관리자만 업로드를 시작할 수 있다.
- 한 소유자에게 동시에 대기 중인 업로드는 최대 3개다.
- 한 팀의 저장 파일 총량은 5GiB 이하다.
- 업로드 URL은 15분 동안 유효하고 완료 시 MIME 유형, 크기, SHA-256을 다시 확인한다.
- 완료 후 24시간 동안 보고서나 결과물에 연결되지 않은 파일은 정리 대상이다.
- 객체 삭제 실패는 지수 백오프로 다시 시도하며 최대 지연은 24시간이다.
- 업로드 정리는 애플리케이션 프로세스 시작 시 실행하고 이후 15분마다 반복한다.
- 연결된 파일의 개별 다운로드 링크는 5분 동안 유효하다.
- 보고서 파일은 해당 팀의 팀원·담당교수·조교·관리자만 내려받는다.
- 종료 프로젝트의 결과물 파일은 학생 공개 프로그램이면 학생, 교수진 공개 프로그램이면 교수진이 내려받을 수 있고 관리자는 공개 설정과 관계없이 접근할 수 있다.
- 팀원·담당교수·조교·관리자는 해당 팀의 연결된 보고서와 결과물 전체를 ZIP으로 내려받을 수 있다.

## 공개 결과물

- 결과물은 파일 하나 또는 HTTPS 외부 링크 하나만 가져야 한다.
- 제목은 1~200자, 외부 링크는 최대 2,048자다.
- 종류는 발표 영상, 소스 코드, 포스터, 기타다.
- `CONFIRMED` 팀의 실행 팀원은 제출 기간에, 관리자는 기간과 관계없이 결과물을 등록·수정·삭제한다.
- 파일 결과물은 같은 팀과 등록자 소유의 완료된 결과물 파일이어야 한다.
- 종료된 프로젝트의 결과물은 해당 사용자 역할에 공개된 프로그램의 지난 프로젝트 아카이브에 노출한다.

## 채점표 정의

- 관리자만 프로그램의 채점표와 항목을 관리한다. 프로그램 종료 여부는 관리 작업을 막지 않는다.
- 채점표 제목은 1~100자이며 같은 적용 범위에서 대소문자를 무시하고 고유하다.
- 채점 마감은 프로그램 운영 기간 안에 있어야 하며 관리자 설정에서는 과거 시각도 허용한다.
- 공개 대상은 운영진 전용 또는 팀원 공개다.
- 항목 이름은 1~60자, 최대 점수는 1~100의 정수다.
- 점수가 하나라도 저장되면 제목·항목·순서·삭제와 분과 상속 방식 변경을 막는다.
- 점수가 있으면 채점 마감을 마지막 점수 저장 시각보다 앞으로 당길 수 없다.

## 공통·분과 채점표

- 분과 미지정 팀과 `INHERIT_COMMON` 분과 팀은 공통 채점표를 사용한다.
- `CUSTOM` 분과는 분과 전용 채점표만 사용한다.
- 공통에서 전용으로 전환하면 현재 공통 채점표와 항목을 복제해 해당 분과 팀에 할당한다.
- 전용에서 공통으로 전환하면 분과 전용 정의·할당을 제거하고 공통 채점표를 할당한다.
- 해당 분과 팀에 점수가 있으면 상속 방식을 바꿀 수 없다.

## 점수와 공개

- 담당교수·조교·관리자는 구성 중이 아닌 팀의 활성 채점표를 마감 시각까지 채점한다.
- 모든 항목 점수를 0부터 항목 최대 점수 사이의 정수로 한 번에 저장한다.
- 팀원 공개 채점표는 모든 항목이 채점되었고 채점 마감 시각이 지난 뒤 실행 팀원에게 보인다.
- 운영진 전용 채점표는 팀원에게 공개하지 않는다.
- 마이그레이션 이전 레거시 평가는 별도 저장된 팀원 공개 플래그를 따른다.
