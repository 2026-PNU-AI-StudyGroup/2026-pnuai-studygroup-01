# 프로그램과 프로젝트 운영 정책

## 프로그램

- 프로그램 생성·설정·학생 공개·교수진 공개·종료는 관리자만 수행한다.
- 새 프로그램은 `ACTIVE`이면서 학생과 교수진 모두에게 비공개 상태로 시작한다.
- 프로그램명은 1~200자, 분류는 1~100자, 설명은 1~5,000자다.
- 같은 시작 시각에 같은 이름을 가진 프로그램을 중복 생성할 수 없다.
- 프로젝트 등록, 모집, 수행, 제출 기간은 각각 시작보다 종료가 늦고 프로그램 운영 기간 안에 있어야 한다.
- 네 기간 사이의 선후 관계나 겹침은 제한하지 않는다.
- 프로젝트 등록·모집·투표는 시작 시각을 포함하고 종료 시각을 포함하지 않는다.
- 기존 보고서 마감이나 확정된 회의가 새 일정 범위를 벗어나도 관리자는 일정을 저장할 수 있다. 관리자 설정 화면은 범위를 벗어난 항목 수를 경고로 보여 준다.
- 학생 공개, 교수진 공개, 운영 종료는 서로 독립된 상태다. 운영 종료만으로 어느 공개 설정도 자동 해제하지 않는다.
- 프로그램 종료 여부는 별도 상태를 저장하지 않고 현재 시각과 `endsAt`만으로 판정한다.
- 관리자가 `지금 종료`를 실행하면 `endsAt`을 현재 시각으로 바꾼다. 종료일을 미래로 연장하면 프로젝트도 저장 상태 변경 없이 다시 진행 상태로 파생된다.
- 관리자는 종료된 프로그램도 기본 정보, 일정, 두 공개 범위, 아이콘, 참여 방식, 분과, 보고서 정의와 채점표를 계속 관리할 수 있다. 각 항목의 형식·참조 무결성 제한은 그대로 적용한다.

## 프로그램 공개 범위

- 학생 공개는 학생의 프로그램·프로젝트 탐색, 프로젝트 지원과 제안, 투표 후보 접근에 적용한다.
- 교수진 공개는 교수의 프로그램·프로젝트 탐색, 교수 프로젝트 등록, 교수 투표 접근에 적용한다.
- 두 공개 범위는 관리자가 각각 설정하며 한쪽 공개가 다른 쪽 공개를 자동으로 바꾸지 않는다.
- 관리자는 두 공개 설정과 관계없이 모든 프로그램에 접근할 수 있다.
- 이미 배정된 실행 팀과 프로젝트 조교의 프로젝트 공간 직접 접근은 프로그램 공개 설정과 분리한다.
- 기존 단일 공개 값에서 두 공개 값으로 전환할 때는 현재 공개 값을 학생 공개와 교수진 공개의 초기값으로 각각 복사해 기존 노출 범위를 보존한다.

## 프로그램 종료의 영향

프로그램 운영 기간이 끝나면 프로젝트의 종료 상태는 즉시 다음처럼 파생한다.

- 확정된 프로젝트 팀이 있으면 `COMPLETED`다.
- 확정된 프로젝트 팀이 없으면 저장된 승인 상태와 관계없이 `CANCELED`다.
- `COMPLETED`와 `CANCELED`는 DB에 저장하지 않는다. 프로젝트의 저장 상태와 프로젝트 팀 데이터도 종료를 이유로 바꾸지 않는다.
- 종료일을 미래로 연장하면 동일한 데이터에서 다시 승인 상태, `FORMING`, `IN_PROGRESS`를 파생한다.

종료 후처리는 cron 또는 관리자의 `지금 종료` 작업이 멱등하게 한 번 수행한다.

- 대기 중인 학생 프로젝트 승인 요청을 취소한다.
- 대기 중인 프로젝트 지원을 자동 미선정하고 결과 알림을 만든다.
- 실행 팀의 공개 모집 글을 닫고 대기 지원을 미선정한다.
- 대기 지도 요청을 취소한다.
- 학생 공개와 교수진 공개 여부는 기존 값을 유지한다.
- 보고서를 자동 승인·반려하거나 별도로 정산하지 않는다. 저장된 보고서와 결정 이력은 현재 상태 그대로 보존한다.
- 후처리 완료 시각은 `endProcessedAt`에 기록한다. 종료일을 미래로 연장하면 이를 비워 다음 종료 후처리를 다시 한 번 실행할 수 있게 한다.

## 프로젝트 등록과 공개

- 교수와 관리자는 프로젝트 등록 기간에 프로젝트를 만들 수 있다.
- 제목은 1~200자, 설명은 1~8,000자, 정원은 1명 이상의 정수다.
- 추가 모집을 받는 프로젝트는 필수 기술, 예상 역할, 활동 가능 시간, 지원 문항이 각각 하나 이상 필요하다.
- 필수·우대 기술은 각각 최대 20개, 항목당 50자 이하다.
- 예상 역할과 활동 가능 시간은 각각 500자 이하다.
- 지원 문항은 최대 20개이고 제목은 1~200자, 답변 제한은 1~5,000자다. 같은 제목의 문항을 중복할 수 없다.
- 분과가 있는 프로그램은 유효한 분과를 반드시 선택하고, 분과가 없으면 분과를 지정할 수 없다.
- 교수·관리자 등록 프로젝트는 생성 즉시 `ACTIVE`가 되며 등록자를 담당자로 지정한다.
- 승인 대기·반려 프로젝트는 공개 시각과 담당자가 없고, `ACTIVE` 프로젝트는 둘 다 있어야 한다.
- 학생 제안 프로젝트의 별도 규칙은 [프로젝트 참여 정책](project-participation.md)을 따른다.

## 프로젝트 수정과 모집 종료

- 관리자는 종료되지 않은 공개·승인 대기·반려 프로젝트의 내용을 수정할 수 있다.
- 담당교수와 프로젝트 조교는 종료되지 않은 담당 프로젝트를 수정할 수 있다.
- 프로젝트를 다른 프로그램이나 분과로 옮길 수 없다.
- 지원서가 한 건이라도 저장되면 지원 방식과 문항을 바꿀 수 없다.
- 정원은 현재 실행 팀원 수보다 작게 줄일 수 없다.
- 프로젝트를 개별 완료·취소·복구하는 작업은 제공하지 않는다. 프로젝트 종료는 프로그램 `endsAt`에만 의존한다.
- 프로젝트 내용 편집은 현재 모집 여부를 그대로 유지하며 모집을 시작하거나 종료하는 수단으로 사용하지 않는다.
- 모집 종료는 프로그램 종료 전의 진행 중인 프로젝트에만 담당교수 또는 관리자가 실행할 수 있다.
- 모집 종료는 프로젝트를 공개 상태로 유지하면서 새 지원을 막고, 대기 지원과 실행 팀 모집 대기 지원을 미선정하며 관련 모집 글을 닫고 감사 기록을 남긴다.
- 종료한 모집을 다시 여는 기능은 제공하지 않는다.

## 관리자 프로젝트 재검토와 승인

- 관리자는 반려 프로젝트를 다시 승인 대기로 보내거나 승인할 수 있다.
- 원시 상태 값을 직접 선택하는 기능은 제공하지 않고 `재검토 요청`과 `승인` 작업을 분리한다.
- `REJECTED -> PENDING_APPROVAL` 전이는 기존 결정자, 결정 시각, 반려 의견을 덮어쓰지 않는다. 기존 요청을 이력으로 보존하고 새 승인 요청을 만든다.
- `REJECTED` 프로젝트를 승인하려면 먼저 새 승인 요청을 만들어 승인 대기로 전환한 뒤 승인 작업을 수행한다.
- `REJECTED/PENDING_APPROVAL -> ACTIVE` 승인은 기존 승인 트랜잭션을 사용해 현재 팀 구성, 활성 계정, 팀 인원과 실행 팀 생성 조건을 다시 검사한다.
- 프로젝트 팀이 이미 만들어진 `ACTIVE` 프로젝트는 승인 대기나 반려 상태로 되돌리지 않는다.

## 분과

- 분과 조회·생성·수정·순서 변경·삭제는 관리자 기능이다.
- 프로그램을 처음 만들 때 분과는 최대 20개까지 지정할 수 있다.
- 분과 이름은 1~40자이며 같은 프로그램 안에서 중복할 수 없다.
- 분과 삭제 시 포함 프로젝트는 미지정 분과로 이동하고 분과 전용 채점표는 제거한다.
- 분과 삭제가 프로젝트 이동, 투표 초기화 또는 투표 범위 변경을 일으키면 현재 영향 수치와 일치하는 재확인이 필요하다.
- 점수가 저장된 분과 팀이 있으면 분과를 삭제할 수 없다.
- 마지막 분과를 삭제하면서 투표 범위가 분과별이면 프로그램 단위로 바꾸고 기존 표를 초기화한다.

## 투표

- 투표 설정은 선택 사항이며 시작·종료, 인당 한도, 프로그램·분과별 한도, 자기 프로젝트 허용 여부를 가진다. 투표는 기명으로 저장한다.
- 분과별 한도는 분과가 하나 이상 있을 때만 설정할 수 있다.
- 로그인한 활성 사용자는 자신의 역할에 공개된 프로그램의 투표 기간에 표를 저장하거나 기존 선택을 전부 교체할 수 있다. 빈 선택은 모든 표 철회로 처리한다.
- 프로그램 운영 종료 여부보다 투표 기간을 우선한다. 역할별 공개 범위에 포함된 종료 프로그램도 투표 기간이 열려 있으면 투표할 수 있다.
- 후보는 같은 프로그램에서 한 번 공개된 `ACTIVE` 프로젝트다. 프로그램 종료 전에는 구성 중 프로젝트도 후보가 될 수 있고, 종료 뒤에는 확정 팀이 있는 완료 프로젝트만 후보가 된다.
- 자기 프로젝트는 작성자, 담당자, 조교 또는 실행 팀원으로 관계된 프로젝트다.
- 관리자는 투표 중 결과 공개와 투표 마감 뒤 결과 공개를 각각 설정한다. 기본값은 투표 중 비공개, 마감 뒤 공개다.
- 학생과 교수는 자신에게 공개된 프로그램에서 해당 시점의 결과 공개 설정이 켜져 있을 때만 후보별 득표수와 순위를 조회한다. 공개 전에는 후보 득표수를 조회할 수 없다.
- 관리자는 결과 공개 설정과 무관하게 전체 결과와 투표자 신원을 조회한다. 학생과 교수에게는 투표자 신원을 공개하지 않는다.
- 투표 기간을 기존 표의 시각 밖으로 줄이거나 기존 자기 표를 남긴 채 자기 투표를 금지할 수 없다.
- 투표 한도나 범위를 바꾸면 정확한 영향 수치를 다시 확인한 뒤 기존 표를 모두 초기화하고 감사 기록을 남긴다.

## 완료·취소 프로젝트와 아카이브

- 완료 프로젝트는 조회자의 역할에 프로그램이 공개된 경우 지난 프로젝트 아카이브에 노출하며 관리자는 공개 설정과 관계없이 조회한다.
- 취소 프로젝트는 탐색·아카이브·대시보드·검색·투표에서 제외하고 직접 URL, 파일, 제출물, 프로젝트 공간도 관리자만 접근한다.
- 완료·취소 뒤에는 관리자도 프로젝트 팀 명단과 팀장을 변경할 수 없으며 운영 쓰기도 금지한다.
- 아카이브 검색은 팀명, 프로젝트명·설명, 공개되는 담당교수명, 기술, 결과물 제목을 대상으로 한다.
- 프로그램 시작 연도는 서울 시간대의 연도로 계산한다.

## 학생 탐색의 졸업과제 임시 숨김

- 내부 사정으로 학생 프로젝트 탐색에서 데모 데이터의 `CSE 캡스톤 디자인` 분류만 임시로 숨긴다.
- 프로그램명이나 분류에 `졸업`, `캡스톤`, `capstone`이 포함됐다는 이유만으로 다른 프로그램을 추측해 숨기지 않는다.
- 교수와 관리자의 탐색에는 이 임시 필터를 적용하지 않는다.
