# 프로젝트 참여 정책

이 문서는 프로그램 안에서 학생이 프로젝트에 참여하는 현재 유효 정책을 정의한다. 정책을 변경하는 코드 작업은 이 문서를 함께 갱신한다.

## 프로그램 참여 방식

프로그램은 다음 두 방식 중 하나로 운영한다. 두 방식은 동시에 활성화하지 않는다.

| 참여 방식 | 학생의 시작점 | 프로젝트 단위 지원 | 적용하는 팀 인원 설정 |
| --- | --- | --- | --- |
| 등록 프로젝트 직접 지원 | 공개된 프로젝트에 개인 또는 팀으로 지원 | 허용 | 팀 지원 최대 인원 |
| 학생 팀 프로젝트 제안 | 기존 학생 팀을 선택해 새 프로젝트를 제안 | 허용하지 않음 | 제안 팀 최소·최대 인원 |

- 기본 팀 최소 인원은 2명, 기본 팀 최대 인원은 6명이다.
- 관리자가 설정할 수 있는 팀 인원은 1명 이상 100명 이하이다.
- 직접 지원형에서는 최소 인원을 사용하지 않으며 저장값을 1명으로 정규화한다.
- 학생 제안형에서는 `최소 인원 <= 최대 인원`이어야 한다.

## 공통 프로그램 조건

- 학생이 이용하는 프로그램은 학생 공개 상태이고 현재 시각이 `endsAt`보다 앞서야 한다.
- 학생 프로젝트 제안은 프로젝트 등록 기간에만 허용한다.
- 직접 지원은 프로젝트 모집 기간에만 허용한다.
- 기간 판정은 시작 시각을 포함하고 종료 시각은 포함하지 않는다.
- 같은 학생이 같은 프로그램의 여러 프로젝트에 참여하는 것은 허용한다. 같은 프로젝트의 활성 팀 멤버십만 중복할 수 없다.

## 등록 프로젝트 직접 지원

- 프로그램의 학생 프로젝트 제안 설정이 꺼져 있을 때만 프로젝트 지원을 노출하고 접수한다.
- 프로젝트의 지원 방식에 따라 개인 지원, 팀 지원 또는 둘 다 허용한다.
- 팀 지원은 학생 팀의 팀장만 제출할 수 있으며 현재 확정 팀원 전체가 함께 지원한다.
- 팀 지원 인원은 다음 두 제한을 모두 충족해야 한다.
  - 프로젝트의 현재 남은 정원
  - 프로그램의 팀 지원 최대 인원
- 지원 접수 시점과 승인 시점 모두 현재 프로그램 참여 방식을 다시 검사한다.
- 팀 지원 승인 시점에는 현재 팀 지원 최대 인원과 프로젝트 남은 정원을 다시 검사한다.
- 지원 문항은 등록된 문항별 필수 여부와 답변 글자 수를 검사하고, 등록되지 않은 문항이나 중복 답변을 허용하지 않는다.
- 개인은 같은 프로젝트에 한 번만 지원할 수 있으며, 팀 지원은 현재 확정 팀원 전원의 지원서를 한 그룹으로 만든다.
- 접수된 지원서를 학생이 수정하거나 철회하는 기능은 현재 없다.

### 직접 지원 검토와 팀 결성

- 담당교수·프로젝트 조교·관리자가 대기 지원을 선정하거나 미선정한다.
- 선정 의견은 선택 사항, 미선정 사유는 필수이며 모두 최대 2,000자다.
- 팀 지원은 그룹 전체를 한 번에 선정하거나 미선정한다.
- 첫 선정이 실행 팀을 `FORMING`으로 만들고 개인 지원자 또는 팀 지원의 기존 팀장을 실행 팀장으로 지정한다.
- 이후 선정은 같은 구성 중 실행 팀에 팀원을 추가한다. 확정·종료 팀에는 더 추가할 수 없다.
- 선정으로 같은 프로젝트 팀에 중복 참여하거나 프로젝트 정원을 넘길 수 없다.
- 정원이 찬 프로젝트의 남은 대기 지원은 그룹 전체를 포함해 자동 미선정한다. 다른 프로젝트의 지원은 유지한다.
- 정원이 차면 실행 팀 모집 글도 닫는다.

## 학생 팀 프로젝트 제안

### 제안 자격

- 학생 팀의 현재 팀장만 제안할 수 있다.
- 제안에는 기존 학생 팀 하나를 반드시 선택해야 한다.
- 선택한 팀의 모든 구성원은 활성 학생 계정이어야 한다.
- 확정 팀원 수는 프로그램의 제안 팀 최소·최대 인원을 충족해야 한다.
- 응답 대기 중인 초대가 하나라도 있으면 해당 팀으로 제안할 수 없다.
- 구성원은 같은 프로그램의 다른 프로젝트에 참여 중이어도 제안할 수 있다.
- 참여 팀 드롭다운에서 `새 팀 만들기`를 선택하면 팀 생성 페이지로 이동하며 작성 중인 제안은 이어지지 않는다.

### 프로젝트 구성

- 학생 제안 프로젝트는 추가 팀원을 모집하지 않는다.
- 지원 방식은 팀 전용으로 고정한다.
- 지원서 문항과 지원 조건을 사용하지 않는다.
- 승인 요청을 저장할 때 프로젝트 정원은 선택한 팀의 현재 확정 인원으로 고정한다.

### 승인 경로

- 지도교수 기능이 꺼진 프로그램은 관리자 승인만 허용한다.
- 지도교수 기능이 켜진 프로그램은 교수 승인 또는 관리자 승인을 선택할 수 있다.
- 교수 승인을 선택하면 활성 교수 한 명을 지정해야 한다.
- 관리자 승인을 선택하면 특정 관리자를 지정하지 않는다.

### 승인 대기와 확정

- 프로젝트 승인 대기 중인 팀에는 새 초대를 보낼 수 없다.
- 팀 구성 변경은 구성 버전을 변경하며 승인자는 현재 구성을 다시 확인해야 한다.
- 승인 시점에 다음 조건을 모두 다시 검사한다.
  - 프로그램이 계속 학생 제안형인지
  - 프로젝트 등록 기간이 열려 있는지
  - 대기 중인 팀 초대가 없는지
  - 팀 구성 버전이 요청 당시와 같은지
  - 현재 팀 인원이 프로그램의 최소·최대 범위 안인지
  - 모든 구성원이 활성 학생인지
- 승인되면 당시 확정 팀원 전원으로 실행 팀을 만들고 즉시 확정 상태로 전환한다.
- 승인 후 학생 팀의 구성 변경은 확정된 실행 팀의 구성원을 자동으로 추가하거나 제거하지 않는다.
- 승인 의견은 최대 1,000자이고, 반려는 사유가 필수다.

## 참여 방식 변경

승인 여부는 요청을 접수했을 때의 참여 방식이 아니라 승인 시점의 현재 참여 방식을 따른다.

- 직접 지원형에서 학생 제안형으로 바꾸면 기존 개인·팀 지원을 승인할 수 없다.
- 학생 제안형에서 직접 지원형으로 바꾸면 기존 학생 프로젝트 제안을 승인할 수 없다.
- 팀 지원 최대 인원을 낮추면 기존 대기 팀 지원도 변경된 최대 인원을 충족해야 승인할 수 있다.

## 화면 노출 기준

- 프로젝트 등록 버튼은 학생 제안형이면서 프로젝트 등록 기간이 열린 프로그램에서 학생에게만 표시한다.
- 프로젝트 지원 버튼은 직접 지원형이면서 모집 기간이 열려 있고 프로젝트에 남은 정원이 있을 때 표시한다.
- 학생 제안형 프로그램에서는 프로젝트 카드의 개인·팀 지원 진입점을 표시하지 않는다.
- 인원 범위를 벗어나거나 응답 대기 중인 초대가 있는 학생 팀은 참여 팀 선택 목록에서 제외하고 제외 사유를 안내한다.
