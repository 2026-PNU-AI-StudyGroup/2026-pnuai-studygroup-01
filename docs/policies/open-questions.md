# 확인 필요 정책

이 문서는 결정이 더 필요하거나 확정된 방향의 세부 범위가 남은 항목만 기록한다. 정책이 확정된 항목은 구현 여부와 관계없이 영역별 유효 정책 문서로 옮긴다.

## 프로젝트 상태와 모집

### 4. 프로젝트 모집 상태를 바꾸는 두 경로

- 프로젝트의 `지원 받기/지원 안 받기` 값은 새 지원 접수 가능 여부를 나타낸다.
- 전용 `모집 마감` 작업은 프로젝트 모집 종료 작업이다. 담당교수·관리자만 실행하고 대기 지원을 모두 미선정하며 실행 팀 모집 글을 닫고 감사 기록을 남긴다. 프로그램 종료일과 프로젝트 종료 상태는 바꾸지 않는다.
- 일반 `프로젝트 내용 편집`의 스위치는 현재 같은 값을 단순히 켜고 끈다. 조교도 사용할 수 있고, 대기 지원 정리나 감사 기록 없이 다시 켤 수도 있다.
- 결정 필요: 내용 편집 스위치를 초기 설정에만 쓰고 공개 후에는 전용 마감만 허용할지, 일반 편집에도 전용 마감과 같은 정리·감사 규칙을 적용할지.

권고: 공개 전에는 스위치로 초기값을 정하고, 공개 후 `지원 안 받기`는 확인 모달이 있는 전용 모집 마감으로만 처리한다. 마감 후 재개는 관리자 전용 별도 작업과 감사 기록을 둔다.

근거: `src/modules/topic/application/change-topic-status.ts`, `src/modules/topic/infrastructure/prisma-topic-command-repository.ts`, `src/modules/topic/application/update-topic.ts`

## 비활성·잔존 모델

- `ProgressUpdate`는 스키마에 있으나 현재 작성·조회 코드가 없다.
- 실행 팀용 `RecruitmentPost`·`RecruitmentApplication`은 종료·정리 코드만 있고 현재 모집 글 생성 진입점은 학생 팀용 모델을 사용한다.
- `TopicApplication`의 `message`, `skills`, `desiredRole`, `availability`는 현재 문항형 지원서에서도 필수 컬럼이라 고정 문구를 저장한다.
- 제거할 레거시인지 향후 복구할 기능인지 결정하기 전에는 유효 정책으로 문서화하지 않는다.
