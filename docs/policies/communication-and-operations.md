# 공지·알림·번역·피드백 정책

## 공지

- 교수와 관리자만 공지를 작성한다.
- 제목은 1~120자, 본문은 1~20,000자다.
- 전체 공지는 로그인 사용자 전체 공개로 고정한다.
- 새 팀 전용 공지와 새 프로그램 구성원 전용 공지는 작성하지 않는다.
- 새 프로그램 공지는 로그인 사용자 전체 공개로만 작성한다.
- 관리자는 전체 공지와 프로그램 공지를 작성할 수 있다. 교수는 자신이 담당하는 프로그램 또는 자신이 담당 프로젝트를 가진 프로그램에 전체 공개 프로그램 공지를 작성할 수 있다.
- 기존 팀 전용 공지와 프로그램 구성원 전용 공지는 모두 목데이터이므로 변환하거나 삭제하지 않고 현재 데이터와 공개 범위를 그대로 유지한다.
- 기존 제한 공지를 전체 로그인 공개로 자동 전환하지 않는다.
- 관리자는 모든 공지를 수정·삭제하고, 교수는 자신이 작성한 공지만 수정·삭제한다.
- 작성자와 관리자는 공개 범위와 관계없이 공지를 볼 수 있다.
- 목록은 고정 공지를 먼저, 이후 최신순으로 정렬한다.
- 프로젝트 탐색의 프로그램 공지 영역은 선택한 프로그램 공지를 보여 준다. 기존 목데이터인 팀 공지는 정리 대상으로 삼지 않는다.

## 알림

- 알림은 사용자별이며 다른 사용자의 알림을 열거나 읽음 처리할 수 없다.
- 알림 링크는 `/`로 시작하는 내부 경로만 허용하고 그 외 값은 알림 목록으로 보낸다.
- 목록은 페이지당 30개, 헤더 미리보기는 3개다.
- 개별 열기와 전체 읽음 처리를 지원한다.
- 지원 결과, 보고서 활동, 지도 요청, 팀 대화, 프로젝트 승인, 마감, 시스템 이벤트를 구분한다.
- 중복 키를 사용해 같은 이벤트 알림을 중복 생성하지 않는다.
- 마감 작업은 현재부터 7일 안의 수행·제출 종료, 미완료 할 일, 미승인 필수 보고서를 팀원·담당교수·조교에게 알린다.
- 마감·번역 작업 API는 32자 이상의 `CRON_SECRET`을 Bearer 토큰으로 받아야 한다.

## 이메일 알림

### 발송 대상 사건

- 아래 사건만 이메일 작업을 만든다. 일반 `SYSTEM` 알림이나 기존 `Notification` 행을 자동으로 이메일로 바꾸지 않는다.
- 기본 발송 사건은 학생 팀 초대, 프로젝트 조교 초대, 팀원 모집 지원 접수·결과·모집 종료, 프로젝트 지원 접수·결과, 프로젝트 등록 승인 요청·결과·취소, 지도·검토 요청 등록·답변·취소, 새 할 일 배정·마감 변경, 프로젝트 구성원 제외·팀장 변경, 마감 임박, 계정 활성화·비활성화·탈퇴, 교수 권한 부여·회수다.
- 마감 알림은 현재부터 7일 안의 수행 종료·결과물 제출 종료, 미완료 할 일, 미승인 필수 보고서를 대상으로 한다.
- 보고서 제출·검토 활동과 프로젝트 토론 글은 선택 발송 사건이다. 두 항목은 모두 기본값이 수신 안 함이며, 로그인 사용자가 계정 설정에서 각각 바꾼다.
- 공지는 생성·수정·삭제·고정·공개 범위와 무관하게 이메일과 인앱 알림을 만들지 않는다.

### 수신자 선정

- 가입된 수신자에게는 검증된 `User.email`이 `@pusan.ac.kr`일 때만 보낸다. `contactEmail`은 이메일 발송에 사용하지 않는다.
- 가입된 수신자는 기본적으로 활성 계정이어야 한다. 계정 비활성화·탈퇴 통지는 해당 계정이 비활성 상태가 된 뒤에도 예외적으로 보낼 수 있다.
- 선택 발송 사건은 작업을 만들 때와 워커가 SMTP를 호출하기 직전에 모두 사용자의 현재 수신 설정을 다시 확인한다.
- 아직 가입하지 않은 대상에게는 학생 팀 초대와 교수 권한 사전 등록만 학교 이메일로 직접 보낼 수 있다. 직접 수신 작업은 가입된 수신자가 삭제되어도 직접 수신으로 재분류하지 않는다.
- 가입 전 직접 수신 작업의 기본 언어는 한국어이며, 가입된 수신자는 `preferredLocale`에 따라 한국어 또는 영어 제목·본문을 받는다.

### 생성과 내용

- 가입된 수신자가 있는 업무 사건은 업무 데이터, 인앱 알림, 이메일 작업을 같은 PostgreSQL 트랜잭션 안에서 기록한다. 가입 전 직접 수신 사건은 이메일 작업만 기록한다.
- 이메일은 업무 내용을 짧게 요약하고 `APP_URL` 기준의 인증이 필요한 PMS 내부 상세 링크를 제공한다. 승인·거절용 토큰과 파일 첨부는 넣지 않는다.
- 동적 제목·본문은 길이를 제한하고 HTML escape 처리한다. 제목에는 `[PNU PMS]` 접두사를 붙인다.
- 사건·업무 식별자·상태 전환·수신자를 기준으로 idempotency key를 만들며, 같은 업무 상태 전환은 이메일 작업을 한 번만 만든다.

### 대기열과 운영

- 이메일은 업무 트랜잭션 안에서 PostgreSQL 아웃박스에 넣고, 별도 Cron 워커가 Gmail OAuth2 SMTP로 한 수신자씩 발송한다. 화면 요청에서 SMTP를 직접 호출하지 않는다.
- 워커는 전역 lease와 작업별 소유자 token을 함께 사용해 동시 워커와 stale 작업을 제어한다. 전달 보장은 정확히 한 번이 아니라 최소 한 번이다.
- 중요 사건을 먼저 처리하며, 24시간 전체 450건·선택 발송 100건을 넘으면 실패시키지 않고 다음 가능한 시각으로 이월한다.
- 네트워크 오류와 SMTP 4xx는 1분·5분·30분·2시간 간격으로 재시도한다. 영구 SMTP 5xx는 실패 처리하며 OAuth `invalid_grant`와 SMTP 535는 배치를 멈추고 관리자 재동의를 요구한다.
- 관리자 화면은 실패 작업을 대기열로 재등록할 수 있지만, 화면 요청에서 SMTP를 직접 실행하지 않는다.
- `SENT`는 Gmail SMTP가 메시지를 접수한 상태일 뿐 받은편지함 도착을 보장하지 않는다. 반송 메일은 발송 계정의 받은편지함에서 운영자가 확인한다.
- 발송 대기·재시도·실패 작업에만 제목·본문·링크를 보관한다. `SENT`·`CANCELED` 전이 시에는 해당 내용을 즉시 삭제하고 상태·종류·시각·시도 횟수 등 운영 집계만 유지한다.

환경 설정, 재시도, 한도, Cron 등록과 장애 복구 절차는 [프로덕션 운영](../PRODUCTION.md)을 따른다.

## 번역과 언어

- 지원 언어는 한국어와 영어다. 로그인 사용자는 계정 설정을, 비로그인 사용자는 언어 쿠키를 사용한다.
- AI 번역은 저장된 사용자 작성 콘텐츠에만 사용하며 운영 판단에는 사용하지 않는다.
- 번역 대상 문자열은 공백을 정리한 1~8,000자다.
- 콘텐츠 저장 시 원문 SHA-256을 기준으로 한국어·영어 번역 작업을 중복 없이 큐에 넣는다.
- 화면은 저장된 번역이 있을 때만 대체하고 없으면 원문을 유지한다.
- 번역 작업은 한 번에 최대 10개, 동시 1개를 처리한다.
- 작업은 최대 5번 시도하고 30초부터 최대 30분까지 지수 백오프한다.
- 10분 넘게 잠긴 작업은 다시 대기 상태로 돌린다.
- 지원하지 않는 언어 작업은 해당 작업만 실패 처리한다.
- 번역 엔진 주소는 HTTP의 `127.0.0.1`, `localhost`, `::1`, `host.docker.internal`만 허용한다.

## 운영 피드백 게시판

- 운영 피드백은 현재 임시 공개 게시판으로 유지한다.
- 피드백 게시판은 로그인하지 않아도 조회하고 글을 등록할 수 있다.
- 작성 이름은 1~40자, 제목은 1~120자, 본문은 1~8,000자다.
- 대상 화면, 기능 영역, 기능 요청·버그 유형, 우선순위를 선택한다.
- 교수와 관리자는 최대 2,000자의 답변을 남기고 해결·미해결 상태를 변경한다.
- 상태 변경은 처리자 이름, 선택적 메모, 변경 시각을 이력으로 남긴다.

## 감사 기록

- 감사 기록은 관리자만 페이지당 50개씩 조회한다.
- 교수 권한, 사용자 활성화·탈퇴, 프로젝트 팀 확정·구성 변경, 프로그램 종료 후처리, 보고서 결정, 조교, 분과, 투표 초기화, 보고서 정의, 채점표 변경을 기록한다.
- 자동 종료 후처리는 행위자 종류를 `SYSTEM`으로 기록하고 사용자 식별자를 두지 않는다.
- 각 기록은 행위자, 대상 유형·식별자, 시각과 작업별 메타데이터를 가진다.

## 상태 점검

- 생존 확인은 애플리케이션 프로세스가 응답할 수 있는지만 확인하고 항상 캐시하지 않는 응답을 반환한다.
- 준비 상태는 데이터베이스와 오브젝트 스토리지가 모두 사용 가능할 때만 성공이다. 둘 중 하나라도 실패하면 HTTP 503을 반환한다.
- 번역 엔진은 2초 제한으로 함께 점검하지만 준비 상태의 성공 여부에는 영향을 주지 않는다.
- 오브젝트 스토리지 점검 제한은 3초다. 모든 상태 점검 응답은 캐시하지 않는다.
