# 공지·알림·번역·피드백 정책

## 공지

- 교수와 관리자만 공지를 작성한다.
- 제목은 1~120자, 본문은 1~20,000자다.
- 전체 공지는 로그인 사용자 전체 공개로 고정한다.
- 새 팀 전용 공지와 새 프로그램 구성원 전용 공지는 작성하지 않는다.
- 새 프로그램 공지는 로그인 사용자 전체 공개로만 작성한다.
- 관리자는 전체 공지와 프로그램 공지를 작성할 수 있다. 교수는 자신이 담당하는 프로그램 또는 자신이 담당 프로젝트를 가진 프로그램에 전체 공개 프로그램 공지를 작성할 수 있다.
- 기존 팀 전용 공지와 프로그램 구성원 전용 공지는 모두 목데이터이므로 변환하거나 삭제하지 않고 현재 데이터와 공개 범위를 그대로 유지한다.
- 기존 제한 공지를 전체 로그인 공개로 자동 전환하지 않는다.
- 관리자는 모든 공지를 수정·삭제하고, 교수는 자신이 작성한 공지만 수정·삭제한다.
- 작성자와 관리자는 공개 범위와 관계없이 공지를 볼 수 있다.
- 목록은 고정 공지를 먼저, 이후 최신순으로 정렬한다.
- 프로젝트 탐색의 프로그램 공지 영역은 선택한 프로그램 공지를 보여 준다. 기존 목데이터인 팀 공지는 정리 대상으로 삼지 않는다.

## 알림

- 알림은 사용자별이며 다른 사용자의 알림을 열거나 읽음 처리할 수 없다.
- 알림 링크는 `/`로 시작하는 내부 경로만 허용하고 그 외 값은 알림 목록으로 보낸다.
- 목록은 페이지당 30개, 헤더 미리보기는 3개다.
- 개별 열기와 전체 읽음 처리를 지원한다.
- 지원 결과, 보고서 활동, 지도 요청, 팀 대화, 프로젝트 승인, 마감, 시스템 이벤트를 구분한다.
- 중복 키를 사용해 같은 이벤트 알림을 중복 생성하지 않는다.
- 마감 작업은 현재부터 7일 안의 수행·제출 종료, 미완료 할 일, 미승인 필수 보고서를 팀원·담당교수·조교에게 알린다.
- 마감·번역 작업 API는 32자 이상의 `CRON_SECRET`을 Bearer 토큰으로 받아야 한다.

## 번역과 언어

- 지원 언어는 한국어와 영어다. 로그인 사용자는 계정 설정을, 비로그인 사용자는 언어 쿠키를 사용한다.
- AI 번역은 저장된 사용자 작성 콘텐츠에만 사용하며 운영 판단에는 사용하지 않는다.
- 번역 대상 문자열은 공백을 정리한 1~8,000자다.
- 콘텐츠 저장 시 원문 SHA-256을 기준으로 한국어·영어 번역 작업을 중복 없이 큐에 넣는다.
- 화면은 저장된 번역이 있을 때만 대체하고 없으면 원문을 유지한다.
- 번역 작업은 한 번에 최대 10개, 동시 1개를 처리한다.
- 작업은 최대 5번 시도하고 30초부터 최대 30분까지 지수 백오프한다.
- 10분 넘게 잠긴 작업은 다시 대기 상태로 돌린다.
- 지원하지 않는 언어 작업은 해당 작업만 실패 처리한다.
- 번역 엔진 주소는 HTTP의 `127.0.0.1`, `localhost`, `::1`, `host.docker.internal`만 허용한다.

## 운영 피드백 게시판

- 운영 피드백은 현재 임시 공개 게시판으로 유지한다.
- 피드백 게시판은 로그인하지 않아도 조회하고 글을 등록할 수 있다.
- 작성 이름은 1~40자, 제목은 1~120자, 본문은 1~8,000자다.
- 대상 화면, 기능 영역, 기능 요청·버그 유형, 우선순위를 선택한다.
- 교수와 관리자는 최대 2,000자의 답변을 남기고 해결·미해결 상태를 변경한다.
- 상태 변경은 처리자 이름, 선택적 메모, 변경 시각을 이력으로 남긴다.

## 감사 기록

- 감사 기록은 관리자만 페이지당 50개씩 조회한다.
- 교수 권한, 사용자 활성화·탈퇴, 프로젝트 팀 확정·구성 변경, 프로그램 종료 후처리, 보고서 결정, 조교, 분과, 투표 초기화, 보고서 정의, 채점표 변경을 기록한다.
- 자동 종료 후처리는 행위자 종류를 `SYSTEM`으로 기록하고 사용자 식별자를 두지 않는다.
- 각 기록은 행위자, 대상 유형·식별자, 시각과 작업별 메타데이터를 가진다.

## 상태 점검

- 생존 확인은 애플리케이션 프로세스가 응답할 수 있는지만 확인하고 항상 캐시하지 않는 응답을 반환한다.
- 준비 상태는 데이터베이스와 오브젝트 스토리지가 모두 사용 가능할 때만 성공이다. 둘 중 하나라도 실패하면 HTTP 503을 반환한다.
- 번역 엔진은 2초 제한으로 함께 점검하지만 준비 상태의 성공 여부에는 영향을 주지 않는다.
- 오브젝트 스토리지 점검 제한은 3초다. 모든 상태 점검 응답은 캐시하지 않는다.
