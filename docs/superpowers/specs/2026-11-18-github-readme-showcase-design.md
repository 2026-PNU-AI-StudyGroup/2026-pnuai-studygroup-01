# GitHub 링크로 프로젝트 카드 채우기 설계

작성일 2026-11-18. 대상 프로그램은 "2026-2학기_Agentic AI Project"(수업). 다른 프로그램에도 그대로 쓴다.

## 배경

수업 결과물을 PMS 에 올리게 하려 한다. 처음에는 MCP 로 학생 AI 도구가 직접 올리게 하려 했다. 그런데 학생이 쓰는 도구가 Claude Code, Claude Desktop, ChatGPT, Codex 로 섞여 있어 연결 방법을 도구마다 가르쳐야 하고, AI 연결 키 발급과 회수까지 새로 만들어야 한다.

대신 학생은 GitHub 링크 하나만 넣고, PMS 가 그 레포의 README 를 읽어 카드를 채운다. README 는 학생이 어차피 쓰는 문서이고, 어떤 AI 도구로든 쓸 수 있다.

## 목표

- 학생이 GitHub 링크 하나로 카드(제목, 설명, 썸네일)를 완성할 수 있다.
- 학생이 직접 넣은 값은 PMS 가 절대 덮어쓰지 않는다.
- README 를 못 읽어도 링크 등록은 성공하고, 학생은 손으로 채울 수 있다.

## 하지 않는 것

- MCP 도구와 AI 연결 키. 이 설계로 대체한다.
- 유튜브 영상 추출. 영상은 선택이고, 넣고 싶으면 쇼케이스 화면에서 직접 넣는다.
- 쇼케이스 소개(showcaseIntro) 채우기. 카드에는 필요 없다.
- README 본문 그림을 쇼케이스 사진 갤러리로 옮기기.
- 비공개 레포 읽기. GitHub 로그인 연동은 하지 않는다.
- README 가 바뀔 때마다 자동으로 다시 읽기.
- 학생에게 나눠 주는 README 양식. 필요하면 매뉴얼에 권장 구조만 적는다.

## 학생 흐름

### 1. 개인 프로젝트 바로 올리기 (프로그램 옵션)

앞서 논의한 설계 1/3 을 그대로 가져온다.

- 프로그램에 옵션 "개인 프로젝트 바로 올리기"를 둔다. 켜면 학생이 만든 프로젝트는 승인 없이 바로 공개되고, 만든 학생 혼자인 1인 팀이 자동으로 확정된다.
- 이 옵션이 켜진 프로그램에서는 학생 1명당 프로젝트 1개만 만든다.
- 운영 프로그램 "2026-2학기_Agentic AI Project" 는 지금 비공개라 시작 전에 공개로 바꿔야 한다.

### 2. 한 화면에서 만들기

프로젝트 만들기 화면 맨 위에 GitHub 링크 칸을 둔다.

1. 학생이 링크를 넣고 "README 가져오기"를 누른다.
2. PMS 가 README 를 읽어 제목, 한두 줄 설명 칸을 미리 채우고 썸네일 후보를 보여 준다.
3. 학생이 고칠 것을 고치고 저장한다. 저장하면 프로젝트, 1인 팀, GitHub 링크(결과물 SOURCE_CODE), 썸네일이 한 번에 만들어진다.

가져오기에 실패해도 학생은 칸을 손으로 채워 저장할 수 있다.

### 3. 이미 있는 프로젝트

자료 추가에서 GitHub 링크(SOURCE_CODE)를 등록하면, 등록 직후 README 를 읽어 **썸네일만** 빈 경우에 채운다. 제목과 설명은 프로젝트를 만들 때 이미 들어가 있으므로 건드리지 않는다.

쇼케이스 화면의 대표 이미지 옆에 "GitHub 에서 다시 가져오기" 버튼을 둔다. README 를 고친 뒤 누르면 다시 읽어 후보를 보여 주고, 학생이 고르면 바뀐다.

## README 읽기 규칙

레포 주소는 `github.com/<owner>/<repo>` 만 받는다. 뒤에 붙은 `/tree/...`, `.git` 등은 기존 `normalizeRepoUrl` 로 정리한다.

1. GitHub API `GET /repos/{owner}/{repo}` 로 기본 브랜치와 레포 설명을 얻는다.
2. `GET /repos/{owner}/{repo}/readme` 로 README 원문을 얻는다.
3. 아래 규칙으로 뽑는다. 기존 `scripts/github-archive.ts` 의 함수를 앱 모듈로 옮겨 쓴다.

| 칸 | 규칙 |
| --- | --- |
| 제목 | README 첫 `#` 제목. 없으면 레포 설명, 그것도 없으면 레포 이름(`pickTitle`) |
| 설명 | README 첫 문단(`readmeTitleAndSummary`). 이메일과 학번은 지운다(`scrubPersonalInfo`). 200자에서 자른다 |
| 썸네일 | README 의 첫 그림(`![]()` 또는 `<img src>`). 상대 경로는 `raw.githubusercontent.com/<owner>/<repo>/<기본 브랜치>/<경로>` 로 바꾼다 |

README 가 템플릿 그대로(`isTemplateRepo` 판정과 같은 기준)면 설명을 비워 둔다. 엉뚱한 안내 문구가 카드에 찍히는 것보다 빈 칸이 낫다.

배지 그림(shields.io, 이름에 `badge` 가 든 주소)은 썸네일 후보에서 건너뛴다.

## 채우는 규칙

빈 칸만 채운다. 아카이브 가져오기(`import-github-archive.ts` 의 ensureThumbnail)와 같은 규칙이다.

- 썸네일: 프로젝트의 대표 이미지(`topic.thumbnailPath`)가 비어 있고, 쇼케이스 사진(결과물 IMAGE)도 하나도 없을 때만 채운다. 학생이 쇼케이스에 이미지를 넣었다면 추출하지 않는다.
- 제목, 설명: 만들기 화면에서 입력칸을 미리 채우는 것까지만 한다. 저장은 학생이 누른다.
- "다시 가져오기"만 예외로, 학생이 후보를 보고 직접 고른 경우에 기존 썸네일을 바꾼다.

## 실패 처리

| 경우 | 화면 안내 |
| --- | --- |
| 레포 없음 또는 비공개 | "레포를 열 수 없어요. 공개 레포인지 확인하거나 칸을 직접 채워 주세요." |
| README 없음 | "README 가 없어요. 칸을 직접 채워 주세요." |
| 그림 없음, 그림 받기 실패 | 제목, 설명만 채우고 "썸네일은 직접 올려 주세요." |
| GitHub 응답 지연(8초 넘음), 요청 한도 초과 | "GitHub 응답이 늦어요. 잠시 뒤 다시 가져오기를 눌러 주세요." |

어느 경우든 링크 등록과 프로젝트 저장은 막지 않는다.

## 보안

- 서버가 남의 주소를 대신 받는 기능이라 받을 수 있는 주소를 묶는다. API 는 `api.github.com`, 그림은 `raw.githubusercontent.com`, `github.com/user-attachments`, `user-images.githubusercontent.com` 만 받는다. 리다이렉트도 같은 목록 안에서만 따라간다. 그 밖의 주소(imgur 등)의 그림은 후보로 쓰지 않는다.
- 그림은 5MB 까지 받고, 기존 업로드와 같은 앞 16바이트 형식 검사를 거쳐 PNG, JPEG, WebP, GIF 만 저장한다. SVG 는 받지 않는다.
- 저장은 기존 파일 저장소(MinIO, stored_file)로 하고, 썸네일 주소는 기존처럼 `/api/files/<id>` 다.
- 요청은 로그인한 학생이 자기 팀 프로젝트에 대해서만 할 수 있다. 결과물 등록 권한과 같다.
- GitHub 비로그인 요청 한도는 서버 IP 당 시간당 60회다. 수업 규모(수십 명)는 충분하지만, 운영 환경 변수 `GITHUB_TOKEN` 이 있으면 붙여 5000회로 올린다. 토큰은 공개 레포 읽기 권한만 준다.

## 구현 위치

- `src/modules/github-readme/`(새 모듈)
  - domain: README 에서 제목, 설명, 첫 그림을 뽑는 순수 함수. `scripts/github-archive.ts` 의 해당 함수를 옮기고, 스크립트는 이 모듈을 가져다 쓰게 바꾼다.
  - infrastructure: GitHub API 와 그림을 받는 클라이언트(주소 목록, 시간 제한, 크기 제한).
  - application: "README 미리보기"(후보 반환)와 "빈 썸네일 채우기" 두 기능.
- 프로젝트 만들기 화면: GitHub 칸과 "README 가져오기" 버튼, 서버 액션 하나.
- `registerArtifactAction`: SOURCE_CODE 이고 GitHub 주소면 등록 뒤 빈 썸네일 채우기를 부른다. 실패해도 등록 결과는 성공으로 돌려준다.
- 쇼케이스 화면(`showcase-manager.tsx`): "GitHub 에서 다시 가져오기" 버튼.
- 프로그램 옵션 "개인 프로젝트 바로 올리기": 스키마 칸 하나와 마이그레이션, 관리자 프로그램 설정 화면 체크박스.

## 시험

- README 추출 함수: 제목 있음과 없음, 첫 문단에 배지만 있는 경우, 템플릿 README, 상대 경로와 절대 경로 그림, `<img>` 태그, 배지 건너뛰기, 이메일과 학번 지우기.
- 주소 검사: 허용 목록 밖 주소, 허용 주소에서 밖으로 가는 리다이렉트 거부.
- 빈 칸 규칙: 대표 이미지가 있을 때, 쇼케이스 사진만 있을 때, 둘 다 없을 때.
- GitHub 클라이언트는 가짜 fetch 로 404, 지연, 한도 초과를 흉내 낸다. 실제 GitHub 호출은 시험에서 하지 않는다.

## 학생 매뉴얼에 넣을 것

- 레포는 공개로 만든다.
- README 맨 위에 `# 프로젝트 이름`, 바로 아래 한두 문장 소개, 그 아래 대표 그림 하나를 두면 카드가 자동으로 채워진다.
- 카드가 마음에 안 들면 쇼케이스 화면에서 직접 바꾸면 된다.

## 남은 결정

- 수업 일정상 배포 마감일. 13주차 전에 운영 배포가 끝나야 한다.
